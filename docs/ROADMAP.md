# BizNexa — Step-by-Step Build Roadmap

Every milestone from [PROMPT.md §13](PROMPT.md) broken into small steps. **Do one step per session/PR.** A step is small enough to build, test and review in one go, so nothing is skipped and any bug is easy to trace back to one step.

Status key: `[ ]` not started · `[~]` in progress · `[x]` done. Tick a step only when its "Done when" is true and tests pass.

---

## How to run a step (protocol for the AI / developer)

1. **Read first.** Open the PROMPT.md sections listed in the step, the related Prisma models in `apps/api/prisma/schema.prisma`, and the existing code in the module. Do not start coding from memory.
2. **Plan in 3–6 bullets** (files to touch, endpoints, schema changes). If the plan touches more than ~10 files or two modules, split the step.
3. **Build only that step.** No "while I'm here" changes in other modules. Note follow-ups in the step instead.
4. **Write tests in the same step** — unit for pure logic (`packages/types`), integration for API endpoints (real DB), Playwright only where the step says so.
5. **Run:** `pnpm typecheck && pnpm lint && pnpm test`. All green before ticking.
6. **Self-review against the checklist below.**
7. **Record:** tick the box here; add any choice the spec didn't cover to `docs/DECISIONS.md`; at the end of a milestone, add a summary to `docs/CHANGELOG.md`.

### Self-review checklist (every step)
- [ ] **AuthZ in the API, not only the UI:** `@RequirePermissions()` on staff routes; customer queries filtered by `userId`; ops filtered by `assignedToUserId` unless `applications.view_all`.
- [ ] **Validation:** shared zod schema in `packages/types`; same schema on web form and API.
- [ ] **Money in integer paise**; GST/coupon maths only through `packages/types` helpers.
- [ ] **State changes go through the state machine** in `packages/types/src/status.ts` → write history + audit log + emit domain event.
- [ ] **Audit log** for every staff write (before/after).
- [ ] **Transactions** for multi-row writes; **idempotency** for webhooks, jobs and retries.
- [ ] **No N+1 queries**; `select` only needed fields; index any new filter/sort column.
- [ ] **No hard-coded services, prices, stages, documents or form fields** (PROMPT rule 1).
- [ ] **Errors:** user-facing messages are clear; no stack traces or secrets leak; no PII in logs.
- [ ] **UI states:** loading, empty, error, mobile width (360px), keyboard focus.
- [ ] **Formats:** ₹ Indian grouping, DD-MMM-YYYY, IST.

### Model per step (to save tokens)
Each open step carries a suggested model tag. Switch with `/model` before starting the step, and start a **new session per step**.
- `[Opus]` — money, payments/webhooks, GST/invoices, concurrency, authorization/data isolation, security, state machines, tricky shared logic. A mistake here is costly, so use the strongest model.
- `[Sonnet]` — the default: normal API + UI features, CRUD with tests, pages, reports, E2E. Good quality at a much lower cost.
- `[Haiku]` — small, well-specified, low-risk steps (simple CRUD/settings, a widget, replacing placeholders). Review the result before ticking.
If a Sonnet/Haiku session gets stuck (same test failing twice, or unsure about the design), switch that step to Opus instead of retrying.

### Prompt template for each step
```

Read the listed PROMPT.md sections and existing code first, show me your plan,
```
